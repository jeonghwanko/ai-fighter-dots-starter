Three ways to make a fighter

Whichever way you choose, the fighter is registered to your own Google account, up to three fighters per account. Pick the way that fits how much you want to do yourself.

Way 01

Leave it to ODDBOUT

On My fighters, describe your fighter in 10 to 600 characters and add up to two pictures you have the right to use. ODDBOUT draws two looks: pick one, or say what to change (twice at most). Then check the motions (three redos at most), confirm the name, profile, lines and stats, and register. One fighter per account is free. ODDBOUT takes a limited number of requests a day; when they are taken, try again the next day.

Way 02

Make it by talking to your agent

In My fighters → “My agents” (the logo button beside the title), press Connect on the agent you use — Grok, Codex (ChatGPT · Dots), Claude or Gemini — and follow its connection steps. Each connects to the ODDBOUT MCP server with your Google account. With the ODDBOUT plugin 0.6.0 or later, ChatGPT already has the connection (https://mcp.oddbout.com/mcp). Grok, Claude and the terminal agents use the address that asks for a sign-in first (https://ztfxxhtmtrvxvuxlqmgz.supabase.co/functions/v1/ai-fighter-mcp/signin, also on their cards). In Claude, choose Register automatically for the OAuth client when you add the custom connector; in a Team or Enterprise organization an owner adds it. Claude Code, the Codex CLI and Gemini CLI connect from a terminal with the one command on their cards, then you sign in in your browser.

Then tell @ODDBOUT in your chat what you want. ODDBOUT makes it the same way as Way 01, and your agent walks you through the choices. To leave the choices to ODDBOUT, say so: you answer once, at the finished motions. Pictures can be attached in ChatGPT only. You can disconnect an agent there at any time.

“@ODDBOUT Make me a small cat boxer with red gloves and an oversized blue hoodie. Pick the look yourself.”

Way 03

Make it on my PC

With a Linux PC and your own ChatGPT and SuperGrok subscriptions, your PC runs the generator for your own fighters: no approval, and no limit of one. In My fighters → “My agents” → Advanced → “Make on my PC”, name your host, accept the host terms and press “Get the PC command”. Paste the three lines into your PC’s terminal within 30 minutes; the code works once. Then choose “My PC” as the maker on My fighters, or ask your agent to make it on your PC. You can disconnect the PC or remove the host in the same place.

To choose every concept and motion yourself with the local creator toolkit, follow the guide from Make it yourself below.

Make it yourself: quick start

You make the creative choices. Your assistant runs the local tools, prepares the files, and shows the results. You do not need to write a character manifest by hand.

  1. Open a new conversation in Dot, Codex, or another assistant that can access local files and run tools on your computer.
  2. Paste the prompt below. Replace the cat boxer with your own idea and attach a reference image if you have one.
  3. Review the first concept before making animations. A browser-only chat without local tool access cannot complete this workflow.

Starter prompt

Read https://github.com/jeonghwanko/ai-fighter-dots-starter/blob/codex/game-context/START-HERE.md
I want to make a fighter for ODDBOUT: a small cat boxer with red gloves and an oversized blue hoodie.
Use the current game requirements and the bundled creation workflow. Check which image and animation tools I can use with my own accounts.
Show me one full-body concept first. Keep the red gloves and oversized hoodie. After I approve the look, show movement, attacks, and reactions in separate review groups.
Let me review the final files before registration.

The sample describes a new fighter; it is not a request to generate anything until you send it to your assistant. No ODDBOUT sign-in is needed for local concept work.

What you need

  • A computer with local tool access. Keep the project in a folder your assistant can read and write.
  • Git, Node.js 22.12 or later, and Python 3.11 or later. Your assistant can check the installed versions before setup.
  • Your own image and animation access. Tool installation does not include a generation subscription or unlimited usage.
  • An idea, reference images, or both. Use references you created or have permission to use, and say what each image is for.

Set up the tools

For the guided route, ask your assistant to set up the linked starter kit. If you prefer to run the setup yourself, use these commands in a terminal. They install the pinned tools in this checkout.

Install the starter

git clone --branch main --single-branch https://github.com/jeonghwanko/ai-fighter-dots-starter.git
cd ai-fighter-dots-starter
npm ci --ignore-scripts
npm run sprite:setup
npm run sprite:status

Use the main branch. A GitHub ZIP omits the submodule contents. sprite:setup fetches the pinned sprite-gen revision and creates its own Python environment. sprite:status checks installation, not subscription or sign-in status.

Installed before 2026-10-29?

The old codex/creator-hosting branch is frozen, and the kit's readiness check stops a checkout on it as the wrong branch. Commit or set aside any local changes, then move the checkout to main. A plain git checkout main fails in the single-branch clone the old instructions made.

Move to main

git remote set-branches origin main
git fetch origin
git switch -C main origin/main
npm ci --ignore-scripts
npm run sprite:setup
Use the toolkit from Codex

From the starter folder, build the ODDBOUT plugin and install it in Codex. The plugin carries the creation skill and the ODDBOUT connection (Google sign-in), so registration works from the same chat. The builder prints the paths and the exact commands.

Build and install the plugin

npm run plugin:build
codex plugin marketplace add <path printed by the builder>
codex plugin add oddbout@ai-fighter-local

Open a new chat and call $create-fighter, or describe the fighter you want. Restart the app if the plugin does not appear. If you move the folder, build again. The older codex mcp add ai-fighter (stdio) connection still works for compatibility.

Create the look

Describe the parts that make your fighter recognizable: silhouette, face, outfit, colors, equipment, and attitude. A short paragraph is enough to begin. A name and biography can come later.

  • Identity reference: keep this face, body, or costume.
  • Style reference: use this kind of linework, color, or shading.
  • Pose reference: borrow the stance or motion, not the whole character.

GROUP 01

Appearance

Review one full-body concept, an idle reference, and a face close-up from the same artwork.

Look for: The same identity from head to toe; readable hands and equipment; the right expression, proportions, and costume.

“Keep the face and colors. Make the gloves larger. Do not start animations yet.”

The game-ready source faces right in an orthographic view with a 16° camera elevation. The toolkit handles the shared scale. A front-facing promotional portrait is not a substitute for the game-ready source.

Make it move

Once you choose the look, review movements in groups. Each group is prepared and shown together. An approval advances the work; a request such as “good, but change the hands” asks for a revision first.

GROUP 02

Stance & movement

Combat idle, 16-frame walk, and 12-frame run. See them at the same scale.

Look for: Alternating feet, stable body size, planted feet that do not slide, and a loop without a visible jump.

“Keep the run. Reduce the bounce in the walk. Leave the outfit unchanged.”

GROUP 03

Attacks

Combo, heavy strike, and dash. Watch the preparation, contact, and return to stance.

Look for: Clear anticipation, readable hits, and a recovery that suits the character’s weight.

“The heavy strike needs a bigger windup. Keep the combo and dash.”

GROUP 04

Defense & reactions

Block, hit reaction, groggy loop, fall, and the linked get-up poses.

Look for: A clear guard; believable impact; a fall that ends lying down. Getting up should play in its own transition.

“Keep the block. Make the fall feel heavier, without changing the face.”

If you want the assistant to handle later groups without review stops, say exactly which ones. You can still request a targeted change. Silence does not approve an unfinished group.

Review & package

GROUP 05

Review the final files

The assistant packages the selected versions, validates the actual files, then shows all motions and the profile from the final package.

Look for: Consistent identity and scale, correct timing and foot contact, the right portrait, name, and description.

“These are the final versions. Validate the package and register it to my account.”

File validation and visual review answer different questions. A valid file can still contain sliding feet, duplicated poses, or the wrong face. Watch the actual final animation before registering.

What the assistant packages

It gathers the approved animations with sprite-gen game-pack, then runs fighter:pack using a generated plan. The packer measures dimensions, origins, contacts, frame timing, and hashes from real files. Walk and run need gait reviews tied to the final pixels and durations.

Example paths — use your actual plan and output

npm run fighter:pack -- path/to/plan.json
npm run validate -- output/my-fighter/fighter.json

Package structure

output/my-fighter/
  fighter.json
  assets/
    idle.webp
    walk.webp
    run.webp
    ...

The submitted art uses static WebP sprite sheets with transparency. GIFs, videos, and animated WebP files are previews, not submission assets. Never invent frame measurements or copy the geometric test bot and call it a new generated fighter.

Register your fighter

  1. Connect your ODDBOUT account. The ODDBOUT plugin, or an agent connected in My agents, signs you in with your own Google account. Use the same account as on the creator page. The workspace needs no separate sign-in.
  2. Ask to register the approved package. The assistant validates the manifest and actual files, then uploads them with prepare_fighter_registration, upload_fighter_asset and submit_fighter_registration.
  3. Wait for the server result. A queued upload is not a completed registration. The assistant checks the submission with get_fighter_submission until it returns a final result.
  4. Confirm the fighter in your account. Completion includes registered, a fighterId, and its current availability. No invitation or manual pre-approval is required. A file-validated fighter starts in production: you can practise with it in the arena, and it stays out of other people's cups, ranked duels and public lists.
  5. Check every motion and enter. On your fighter's page, open All motions: play each motion, slow it down or step through it, and tick each of the 11 required motions once it looks right. Then press Enter ODDBOUT; other people can now play against your fighter in cups and ranked duels. A new package returns the fighter to production until you check it again.
Retries and the older sign-in

For an unchanged upload, keep the same idempotency key when retrying. Changed files need a new key. If the result is unknown, inspect the existing submission before uploading again. Registered packages are immutable; content can be restricted after publication.

The older local tools without the ODDBOUT connection sign in with npm run login (add --device on a computer without a browser). Open the sign-in link yourself, approve only a code you started, and do not share the session file.

Revise & resume

Name the motion or image you want to change, what should change, and what should stay. Keep approved versions; do not regenerate the entire fighter for a small edit.

“Resume the cat boxer. Keep the approved face, outfit, and run. Only shorten the combo recovery. Show the revised combo before repackaging.”

The assistant keeps a local work note with selected file paths, versions, feedback, and the next review group. For a new conversation, point it to the same project folder and that note. A body or costume change may affect several animations; review the affected groups again. Metadata-only edits need fresh file validation, not another review of unchanged art.

Troubleshooting

The tools do not appear in my chat.

Check that the ODDBOUT plugin is installed, or that the agent is connected in My agents, then open a new conversation or restart the app. For the local toolkit, build the plugin again if the folder moved.

Grok shows ODDBOUT as connected but cannot use my account.

Grok was added with https://mcp.oddbout.com/mcp, which it reads as needing no sign-in. Remove the connector and add Grok’s own address https://ztfxxhtmtrvxvuxlqmgz.supabase.co/functions/v1/ai-fighter-mcp/signin: it asks for a sign-in when you connect, and Grok then shows Connected in My agents.

Claude cannot add or use ODDBOUT.

In a Team or Enterprise organization, only an owner can add a custom connector (organization settings → Connectors); members then press Connect. Use the address on the Claude card, which asks for a sign-in, and choose Register automatically, not Claude’s published identity. A connector added before with No sign-in reaches only the public tools, and that choice cannot be changed: remove it and add it again with that address. If adding says the server could not be checked, try again a moment later.

The sign-in from a terminal agent does not finish.

The sign-in comes back to the app on your computer, so finish it in a browser on the same computer. On a computer you reach over SSH, or in a container, the browser cannot reach it. The approval page says the connection goes to an app on this computer: approve only a connection you just started.

ODDBOUT appears twice in ChatGPT.

The ODDBOUT plugin 0.6.0 or later already carries the connection. Remove the custom MCP server you added separately.

ODDBOUT refused my request.

One fighter per account is free on ODDBOUT, and ODDBOUT takes a limited number of requests a day. Make more on your own PC (Way 03), or try again the next day.

A generation tool fails or reaches its limit.

Keep the selected work and inspect the request and any existing output before retrying. Follow your chosen stop or fallback policy. Do not treat an unknown result as proof that nothing was generated.

The feet slide or the body jumps between frames.

Revise the affected walk or run and check both feet, common scale, ground contact, and loop boundaries. Repeating a still frame or changing playback speed is not a substitute for valid movement.

Validation failed.

Read the reported stage and error path. Fix that file or motion, then validate again. A metadata-only pass does not mean the actual images or visual motion passed.

Registration is queued, rejected, or missing from my account.

Check the existing submission first. Queued work may be waiting for the validator. Rejected packages include errors to fix. For a registered fighter, confirm the same Google account and current availability before submitting anything again.

Technical reference

The table below explains the current 11-motion set. The live game context and schema remain the source of truth. Your assistant refreshes them at the start, on resume, before each new group, and before packaging. If requirements change, preserve the existing work and review the differences.

MotionPurposeFrames
idleStill full-body pose1
fightIdleCombat-ready loopCurrent contract
walkOne walking cycle, alternating feet16
runOne running cycle12
comboCombo: preparation, strikes, recoveryCurrent contract
slamHeavy strikeCurrent contract
dashLunge, including preparation and recoveryCurrent contract
blockGuard and blockCurrent contract
hitRecoil, stagger, recoveryCurrent contract
groggyDazed loopCurrent contract
fallFall and lie down; linked get-up posesCurrent contract

The appearance baseline uses a 400 px body height; this is not the same as sheet-cell height. Assets use one shared coordinate and scale reference. Artwork defines the look and motion; HP, damage, executable code, and gameplay rules are not creator-supplied character fields.
