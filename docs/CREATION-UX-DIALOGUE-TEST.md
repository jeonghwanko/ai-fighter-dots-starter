# 16개 시나리오 대화 UX 평가 — 2026-10-21

## 결과

**16개 시나리오 범주를 실제 모의 응답으로 점검했다.** 별도 기존 대화의 링크 진입 응답 1개와 두 배치의 응답 6+15개, 총 22개를 읽고 수동 평가했다. 실제 캐릭터·이미지·영상 생성, 로그인, 과금 호출, 등록은 이번 시험에서 실행하지 않았다.

관찰한 응답은 모두 기대한 다음 단계·대기 범위를 설명했다. 사용자에게 보낼 문구에서는 **수정본 제시 전 선택 요청**, **접근 실패 시 중단 방침 누락** 두 문제를 발견해 가이드에 반영했다. 위임 적용 순서도 더 분명히 썼다. 별도 문서 검토에서는 아래 경계 규칙 7개를 보완했다.

이 결과는 대화 방향과 문구에 대한 제한된 판단이다. 전체 제작 품질 점수나 개선율은 산출하지 않는다. **수정된 로컬 가이드 전체를 새 모델로 다시 실행한 전후 비교 시험은 아니다.**

## 실제 관찰 근거와 조건

- 관찰 대화: “AI Fighter 개선 가이드 대화 검증” (`01a15d79-33bd-7182-a3e4-04eb249d0e50`). 이 작업에서는 읽기만 했으며 새 메시지를 보내거나 새 대화를 만들지 않았다.
- 처음 읽은 가이드: `d6d561b89d36779e44f8db7567495575f7a58587`. 이후 같은 대화 맥락에서 모의 응답을 받았다.
- 21개 사례는 2개 턴에서 묶어 답했다. 21번의 독립된 실행이나 실제 다중 턴 사용자 시험이 아니다.
- 두 모의 응답 턴의 실행 도구 호출은 각각 0개였다. 링크 진입 턴은 문서·맥락을 읽었고 생성하지 않았다.
- 초기 턴이 원본 작업을 조회해 완전히 격리된 첫 사용자 검증은 아니다.
- 이미지 내용, 로그인 준비, 요청 ID, 패키지·검사 상태는 텍스트로 제공한 가상 상태다. 실제 이미지 인식·제작·복구·등록 성공은 미검증이다.
- 원본 요청과 최종 응답을 보존했고, 별도 read_thread 결과와 응답이 일치함을 확인했다. 이후 “이걸 적용해줘” 구현 턴은 모의 시험 집계에서 제외했다.

## 실제 모의 입력·응답 원문

B1은 6개 배치, B2는 15개 배치다. 이 식별자는 아래 정답 예시의 분기 ID와 별개다. 응답 안의 “만들겠습니다”·“조회하겠습니다”는 가상 상황의 예정 행동이며 실제 실행 보고가 아니다.

### ENTRY · U01

입력·가상 상태: https://github.com/jeonghwanko/oddbout-starter/blob/codex/creator-hosting/docs/START-HERE.md

실제 받은 응답: 어떤 캐릭터를 만들고 싶으세요? **한두 문장으로 설명하거나, 참고 이미지와 바꾸고 싶은 점을 보내주세요.**

예를 들어 “커다란 장갑을 낀 느긋한 곰 복서, 부드러운 만화풍”처럼 알려주시면 됩니다. 이미지가 있다면 “얼굴은 유지하고 옷만 바꿔줘”라고 설명해도 좋아요.

먼저 외형 시안을 함께 다듬고, 선택한 뒤 **대기·이동 → 공격 → 방어·피격** 순서로 묶음마다 결과를 확인하며 진행하겠습니다.

기대: 텍스트·이미지 입력 안내 후 대기.

평가: 관련 문서 외 원본 대화도 읽었으므로 격리된 첫 사용자 시험은 아님.

근거 턴: `01a15d79-4031-7410-863c-ce5b8cbb7320`.

### B1-A · U10

입력·가상 상태: 외형 미리보기를 이미 보여준 가상 상태에서 사용자가 '좋은데 귀는 조금 줄여줘'라고 답했습니다.

실제 받은 응답: “다른 특징은 유지하고 귀만 조금 줄이겠습니다. 기존 시안과 수정본을 함께 보고 골라주세요.”

모델이 답한 예정 범위: 기존 시안 보존 → 귀 수정본 제시 → 외형 피드백 대기. 동작으로 넘어가지 않음.

기대: 귀 수정본을 제시하고 외형 선택 대기.

평가: 작업 범위는 맞지만 수정 전 “골라주세요”가 성급함. 실제 수정본 뒤에 질문하도록 문구 수정.

근거 턴: `01a15d7a-51b3-7d70-889d-582c71de8a56`.

### B1-B · U11

입력·가상 상태: 대기·걷기·달리기 미리보기를 보여준 가상 상태에서 '달리기는 좋아'라고 답했습니다.

실제 받은 응답: “달리기는 유지하겠습니다. 전투 대기 자세와 걷기는 어떤가요?”

모델이 답한 예정 범위: 달리기에 대한 긍정 피드백만 기록. 대기·걷기 피드백 대기.

기대: 달리기만 선택하고 나머지 피드백 대기.

평가: 불필요한 재질문·묶음 이탈 없음.

근거 턴: `01a15d7a-51b3-7d70-889d-582c71de8a56`.

### B1-C · U11

입력·가상 상태: 대기·걷기·달리기 전체 미리보기에 '셋 다 좋아. 다음으로 가자'라고 답했습니다.

실제 받은 응답: “대기·걷기·달리기는 이 버전으로 확정하고, 연타·강타·돌진을 만들겠습니다. 세 공격을 함께 보여드리면 힘과 박자를 확인해주세요.”

모델이 답한 예정 범위: 공격 묶음의 생성·검수·미리보기까지 진행한 뒤 피드백 대기.

기대: 현재 이동 묶음 확정 후 공격까지만 진행.

평가: 불필요한 재질문·묶음 이탈 없음.

근거 턴: `01a15d7a-51b3-7d70-889d-582c71de8a56`.

### B1-D · U12

입력·가상 상태: 외형이 선택된 가상 상태에서 '대기·이동은 같이 보고 정하자. 공격 묶음과 방어·피격 묶음은 맡길게'라고 답했습니다.

실제 받은 응답: “먼저 대기·이동을 만들어 함께 정하겠습니다. 그 묶음이 확정되면 공격과 방어·피격은 맡겨주신 범위대로 이어서 만들고, 전체 결과를 보여드리겠습니다.”

모델이 답한 예정 범위: 대기·이동 끝에서 피드백 대기. 확정 후 공격과 방어·피격을 연속 진행하고 최종 확인에서 대기. 등록은 포함하지 않음.

기대: 이동 리뷰 유지 후 위임한 두 묶음 진행.

평가: 전환 범위는 맞음. 선행 이동 선택이 위임 적용 조건임을 더 분명히 표시.

근거 턴: `01a15d7a-51b3-7d70-889d-582c71de8a56`.

### B1-E · U07

입력·가상 상태: 캐릭터 설명을 받은 뒤, 사용자가 본인의 GPT와 Grok 생성 구독을 모두 현재 사용할 수 있다고 답했고 별도 제공자 선호는 없습니다.

실제 받은 응답: “원화는 GPT, 동작은 Grok으로 진행하겠습니다. 먼저 전신 시안과 같은 그림의 얼굴 확대를 보여드리겠습니다.”

모델이 답한 예정 범위: 구독을 다시 묻지 않고 현재 외형 단계 준비. 외형 선택 전 동작 생성 없음. 접근 실패 시 알리고 중단하며 임의 전환하지 않음.

기대: GPT 원화·Grok 동작, 접근 재질문 없이 외형부터.

평가: 내부 작업 범위에는 중단 정책이 있으나 사용자 답변에는 누락. 최초 진행 안내에 드러내도록 수정.

근거 턴: `01a15d7a-51b3-7d70-889d-582c71de8a56`.
