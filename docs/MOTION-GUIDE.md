# 모든 모션의 생성 전 가이드

새 캐릭터와 기존 캐릭터 수정에서 `idle`, `fightIdle`, `walk`, `run`, `combo`, `slam`, `dash`,
`block`, `hit`, `groggy`, `fall` 및 별도 기상 자세에 공통 적용한다.
목표는 생성 전에 자세와 연결을 구체화해 시행착오를 줄이는 것이다. 가이드 작성은 추가 생성이나 구독 변경의 승인이 아니다.

정확한 모션·프레임·시간·이벤트 계약은 현재 게임 응답과 [AUTHORING.md](AUTHORING.md)가 소유한다.
사용자 피드백·위임 범위는 [CREATION-UX.md](CREATION-UX.md), 실행·전달은
[DOT-CREATION.md](DOT-CREATION.md)와 [DELIVERY.md](DELIVERY.md)를 따른다.
이 문서는 기존 도구 스키마를 바꾸거나 새 필수 JSON·명령을 도입하지 않는다.

## 1. 외형과 공통 좌표를 먼저 고정한다

원화가 없는 첫 `idle`은 사용자 설명·참조에서 체형과 구도를 설계하고 외형 시안으로 확인한다.
별도 AI 가이드 생성을 선행 조건으로 추가하지 않는다. 원화가 선택된 뒤 아래 기준을 다른 모션에 공유한다.

- 선택된 원화의 실제 파일·버전과 사용자가 유지하라고 한 특징을 기준으로 삼는다.
  머리/몸통 비율, 팔다리 길이, 얼굴·귀·옷·장비·색을 현재 캐릭터에서 읽는다. 다른 캐릭터의 수치를 복사하지 않는다.
- 한 묶음은 카메라, 방향, 캔버스, 여백, 중립 자세의 배율을 공유한다.
  웅크림·피격·누움마다 외곽 높이를 다시 맞추지 않는다. 배율 기준은 보이는 몸 표식으로 잡는다.
- 가이드는 완성될 전신의 실루엣, 관절 연결, 손발 방향, 얼굴·옷의 주요 경계까지 표현한다.
  뼈대만으로 체형·가려짐을 해결했다고 보지 않는다. 이미 같은 조건에서 검토한 가이드는 재사용한다.
- 가까운 팔다리와 먼 팔다리는 자연스러운 명암·겹침·윤곽으로 구별한다. 보이지 않는 관절은 설계 가정으로 남긴다.
  접지발, 들어 올린 발, 공중 자세, 넘어져 몸이 닿는 부위는 동작에 맞게 설계한다.
  모든 모션에 평평한 양발 접지나 같은 발 높이를 강요하지 않는다.
- 검토용 관절·지면선·설명 표시는 실제 생성에 넣는 이미지와 구분한다.
  도구가 요구하는 guide 형식은 유지하고, 화면 밖 X-ray 관절이나 라벨을 실제 가시 부위로 해석하지 않는다.

## 2. 자세와 외형 참조의 역할을 분리한다

각 호출의 목표 자세 또는 목표 시퀀스를 하나의 기준으로 정한다. 참조마다 역할을 먼저 적는다.

| 참조 역할 | 포함할 정보 | 피할 충돌 |
| --- | --- | --- |
| 목표 가이드 | 이번 전신 자세 또는 순서가 있는 동작, 카메라·배율·몸/손발 위치 | 서로 다른 목표 자세를 동등한 기준으로 전달 |
| 외형 원본 | 선택된 캐릭터의 얼굴·체형·복장·색·화풍 | 중립 원화의 서 있는 자세까지 따라 하게 만드는 지시 |
| 연결용 앵커 | 필요하거나 선택한 도구가 요구하는 검토된 시작·끝·인접 자세 | 목표 다리 교대나 피격 방향과 충돌하는 다른 자세를 무조건 추가 |

참조를 많이 넣는 것을 기본 개선책으로 삼지 않는다. 자유로운 다중 이미지 편집에서는
**목표 가이드 + 외형 참조**를 우선 검토한다. 전신 외형 참조가 자세와 경쟁할 가능성이 있으면,
원본의 얼굴·귀·옷·장비 부분을 외형 참고로 분리할 수 있다. 부분 참조는 원본에서 나온 자료임을 기록하고,
빠진 전신 비율은 목표 가이드에 남긴다. 참고용 모음판을 생성 결과나 합성된 최종 캐릭터로 제출하지 않는다.

추가 앵커는 연결에 필요한 경우에만 사용하고, 목표와 다른 자세 정보가 어떻게 해석되어야 하는지 명시한다.
단, 선택한 `gen-motion`·행 생성·영상 경로가 요구하는 원화, phase-guide, keyposes, 시작/끝 참조는
임의로 제거하거나 외형 crop으로 대체하지 않는다. 그 경로의 지원 형식 안에서 역할을 분리한다.
가이드·프롬프트·실제 참조 목록이 같은 설계를 가리키는지 확인한다.

## 3. 한 장보다 전체 동작의 연결을 먼저 설계한다

정지 자세는 전신 가이드 하나면 충분하다. 움직이는 동작은 준비 → 핵심 자세 → 복귀 또는 루프의
순서·리듬·몸의 이동·가려짐을 먼저 정한다. 각 프레임을 독립적으로 그려 놓고 나중에 연결을 추측하지 않는다.
다음 표는 설계 관점이며, 프레임 수와 이벤트 인덱스의 별도 규격이 아니다.

| 모션 | 생성 전 가이드에 담을 것 | 실제 결과에서 우선 볼 것 |
| --- | --- | --- |
| `idle` | 중립 전신, 공통 비율·시점·기준점 | 정체성, 전신 보존, 다른 동작의 크기 기준 |
| `fightIdle` | 가드 시작·호흡/체중 이동·가드 복귀 | 손 위치, 전신 움직임, 루프 연결 |
| `walk` | 양발의 지지·회수 교대, 몸/팔 위상, 지면 관계 | 실제 물리발 교대, 지지 구간 이동, 접지와 루프 |
| `run` | 양쪽 반주기의 지지·추진·공중·착지, 다리 회수 | 양발 교대, 실제 보이는 공중 구간, 속도·착지·루프 |
| `combo` | 준비·각 접촉·회수, 회전 구간과 팔/장비 경로 | 연타 구분, 몸 회전, 접촉 박자와 복귀 |
| `slam` | 준비·힘을 모음·한 번의 강타·회수 | 타격 방향, 힘 전달, 한 번의 접촉과 회수 |
| `dash` | 준비·전진·타격 또는 통과·회수, 몸과 발의 관계 | 전진 방향, 발/몸 이동, 준비·회수 연결 |
| `block` | 유지 가드·충격 흡수·가드 회복 | 막는 방향, 손/장비 위치, 충격 전 가드 |
| `hit` | 충격을 받는 방향·최대 반동·비틀거림·가드 복귀 | 공격처럼 보이지 않는 반응, 상체/팔/발의 연속 복귀 |
| `groggy` | 중심이 흔들리는 범위·균형 회복·반복 | 흔들림과 체형 유지, 루프 연결 |
| `fall` | 균형 상실·넘어짐·착지·누워 멈춤 | 낙하 방향, 착지, 마지막 누운 자세 |
| 기상 보조 | 누움·몸 일으킴·가드로 복귀, fall과 같은 좌표 | 누움에서 연결, 공통 배율, fall 재생과 분리 |

핵심 자세 사이의 차이가 크면 중간 가이드부터 보완한다. 피격 최대 반동 다음에 곧바로 중립을 배치하거나,
팔을 내린 자세 다음에 완전한 가드를 붙여 모델이 연결을 알아서 만들 것이라 기대하지 않는다.
가이드 위상·접촉 시점은 목표다. 최종 이벤트와 검수값은 실제 결과의 재생에서 정한다.

## 4. 선택한 생성 경로에 맞는 입력을 만든다

| 경로 | 같은 원칙을 적용하는 방법 |
| --- | --- |
| 한 장/단일 전신 포즈 편집 | 한 요청에 한 자세. 목표의 팔다리 배치와 외형 참고 역할을 명시 |
| 행·시퀀스 생성 | 도구의 배치 가이드와 함께 순서·위상·검토된 핵심 자세를 전달. 한 칸용 프롬프트를 전체 행에 그대로 쓰지 않음 |
| 영상 생성 | 시간 순서, 카메라 고정, 준비·동작·복귀/루프를 설명. 지원되는 시작·끝·참조 입력만 사용 |

프롬프트는 **보여야 할 상태 → 자세·지지/공중·방향 → 외형 → 카메라·구도·배경** 순으로 쓴다.
이미지 편집에서는 바꿀 자세를 먼저 지정하고 보존할 외형·시점을 짧게 덧붙인다.
긴 금지 목록, 서로 다른 자세를 요구하는 문장, 도구가 지원하지 않는 강제 좌표·참조 가중치는 넣지 않는다.
모든 동작에 같은 문장을 복사한 뒤 모션 이름만 바꾸지 않는다.

단일 자세 프롬프트 예시:

> 목표 가이드의 짧고 두꺼운 체형으로 오른쪽을 보는 전신 공중 자세.
> 가까운 다리는 앞쪽 높게, 먼 다리는 뒤쪽 낮게 두고 두 발의 윤곽을 구분한다.
> 외형 참고에서는 얼굴·귀·복장·색만 가져온다. 목표 가이드의 몸 위치, 배율, 시점과 여백을 유지한다.
> 선택한 출력 방식에 맞는 배경으로 캐릭터 한 명을 그린다.

피격 복귀 자세에서는 첫 두 문장을 “상체는 최대 반동에서 절반 돌아오고, 양손은 낮은 가슴까지 올라오는
중간 가드”처럼 해당 순간의 몸·팔 상태로 바꾼다. 정지 그림에 시간 순서 전체를 동시에 그리라고 하지 않는다.

Grok 다중 이미지 편집 등 참조 기반 생성은 관절 좌표를 강제로 고정하는 장치가 아니다.
상세 가이드만으로 성공률이나 픽셀 일치를 보장하지 않는다. 모델·제공자·구독·과금 경로는 사용자의 선택을 유지한다.
추가 구독이나 별도 GPU 서버를 공통 가이드의 숨은 전제로 만들지 않는다.

## 5. 입력은 한 번 검토하고, 결과는 묶어서 검수한다

생성 전에 현재 묶음의 **실제 입력 가이드·참조 이미지·최종 프롬프트·출력 설정**을 함께 확인한다.
그림의 비율·손발 구분·가려짐·연결과 파일의 캔버스·참조 순서를 확인하며, 좌표표만 보고 준비 완료로 쓰지 않는다.
검토한 입력의 경로·버전을 기존 작업 기록에 남긴다. 입력이 바뀌지 않았으면 같은 준비 검토를 반복하지 않는다.
가이드의 내부 검토를 매 장마다 사용자에게 새 승인을 묻는 절차로 만들지 않는다.

새 생성 방식·새 체형의 어려운 동작이나 반복된 결함을 다룰 때는, 합의된 생성 범위에서
그 결함을 판별할 최소 대표 자세를 먼저 확인한다. 이미 같은 조건에서 통과한 경로에 매번 별도 시험 생성을 추가하지 않는다.
완료된 원본은 보존하고, 합의된 묶음의 실제 정상/느린 재생을 함께 검수한다. 정지 동작에는 정지 미리보기를 쓴다.

- 우선 결함: 다른 캐릭터, 잘림/추가·끊긴 팔다리, 잘못된 방향·발 교대·공중/접지,
  큰 크기 변화·지면 튐·프레임 연결 끊김, 필요한 이벤트·루프·복귀 누락.
- 작은 옷 주름·표정·가이드와의 미세한 차이는 사용자 필수 특징, 정체성, 연결과 규격을 해치지 않으면 받아들인다.
  수치 계약의 실패를 미적 차이라고 축소하거나 허용치를 바꾸어 통과시키지는 않는다.
- `walk`/`run`은 [GAIT-REVIEW.md](GAIT-REVIEW.md)의 실제 양발·접지·최종 픽셀/시간 검수를 유지한다.
  `hit` 등 액션에 같은 gait 전용 검사나 고정 양발 접지를 강제하지 않는다. 액션도 방향·균형·지면 관계·연결은 검수한다.
- 명백히 포즈가 틀렸으면 전체 시퀀스를 확장하거나 세밀한 접지 수치를 반복 측정하지 않는다.
  실패 유형을 기록하고 입력의 자세 충돌·체형·가려짐·복귀 구간부터 고친다. 다른 통과 동작은 보존한다.
- 같은 해부·접지·방향/교대 결함이 두 번 연속 남으면 동일 방식의 생성을 멈추고 한계와 변경안을 제시한다.
  다른 참조 구성이 해결책이라는 판단은 검증 전 가설로 기록한다. 같은 입력 재호출이나 문구만 바꾼 무한 반복을 하지 않는다.
- 완료 여부 불명·전달 실패는 미술 실패와 구별한다. 기존 요청/파일을 먼저 회수하며,
  입력 개선을 명분으로 불명 요청을 다시 보내지 않는다. 새 요청은 기존 사용자 승인 범위와 중복 사용량 규칙을 따른다.

사용자에게는 기존 묶음 경계와 실제 위임 범위에 맞춰 결과를 보여준다. 수정한 결과만 재검수하고,
패키징 후 필수 검사는 최종 픽셀·시간에 연결한다. 이미 통과한 검사를 근거 없이 반복하거나 필수 검사를 생략하지 않는다.

## 작업 기록 예시

다음 항목은 기존 `creation-notes.md`나 도구가 사용하는 계획에 필요한 만큼 기록한다. 새 양식을 사용자에게 채우게 하지 않는다.

```text
모션/버전과 현재 묶음:
유지할 원화·선택 동작:
공통 카메라·캔버스·중립 배율 기준:
준비 → 핵심 자세 → 복귀/루프와 목표 시간:
목표 가이드 / 외형 참고 / 필수 또는 선택 앵커의 파일·역할:
가려진 부분의 설계 가정:
이전 실패에서 바꾼 입력과 확인할 핵심 차이:
검토한 실제 입력·프롬프트 버전과 승인된 실행 범위:
생성 결과·관측·전달·검수·사용자 선택: 각각 따로 기록
```

## 근거와 적용 한계

[xAI 이미지 프롬프트 지침](https://docs.x.ai/developers/model-capabilities/images/prompting-guide)은
구체적인 상태·시각 특징, 원하는 결과를 서술하는 문장, 편집할 대상부터 설명하는 방식을 권한다.
[다중 이미지 편집](https://docs.x.ai/developers/model-capabilities/images/multi-image-editing)은 여러 참조 입력을 지원한다.
외형 부분 참조가 포즈 간섭을 줄인다는 것은 이 제작 흐름의 검증 가능한 설계 가설이다.
공식 문서가 관절 고정이나 이 방법의 성공률 향상을 보장한다고 설명하지 않는다.
