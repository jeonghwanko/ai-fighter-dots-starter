# 분리된 접촉면·들린 뒤꿈치 검토

`fighter:contact`는 AI Fighter 제작 키트가 유지하는 **명시적 검토 근거 확장**이다. 번들 sprite-gen 소스와 핀을 바꾸거나
공식 모듈을 monkey-patch하지 않는다. 기본 `inspect-motion`은 그대로이며, `footEvidence`를 지정한 접지 구간만 확장을 사용한다.
확장 보고서에는 공식 `upstream_report` 전체와 적용 근거가 함께 남는다. 공식 sprite-gen이 수정됐다고 표현하지 않는다.

## 지원 범위와 한계

공식 검사기의 하단 2픽셀 띠는 부츠의 굽과 앞창도 두 접촉면으로 볼 수 있다. 반면 연결된 두 발도 비슷한 모양을 만들 수 있다.
따라서 연결성·일정한 이동만으로 경고를 제거하지 않는다. 검토자가 실제 프레임마다 **양쪽 해부학적 발 전체**를 구분해서
표시하고 같은 발·발 전체·반대 발 제외·지면 접촉을 모두 확인해야 한다. `near`/`far`는 화면상 앞뒤에 따라 바꾸지 않는다.

이 선언은 시각 검토에 의존한다. 잘못된 해부학적 라벨이나 거짓 검토를 이미지 마스크만으로 완전히 검출할 수 있다고 주장하지 않는다.
가림 때문에 두 발을 구분하거나 발 전체를 표시할 수 없으면 `unverified`로 유지한다. 로컬 제작 근거이며 서버 보안 인증서가 아니다.

근거 파일은 두 판이 있다. 새 템플릿은 v2(`ai-fighter-foot-evidence-v2`)이고, 이미 만든 v1 파일은 v1 규칙 그대로 검사한다.
v1만 다시 만들려면 `template`에 `--evidence-version 1`을 준다. 두 판 모두 아래 공통 조건과 윤곽 요구는 같다.

### v1: 부츠 굽·앞창 두 접촉면

v1은 다음을 모두 요구한다.

- 전체 시퀀스 RGBA 픽셀·프레임 크기·재생 시간, 발 이름·접지 구간·ROI·방향이 템플릿 생성 당시와 일치한다.
- 모든 접지 프레임에 두 발의 단순 다각형 윤곽과 굽·앞창 접촉점이 있다. 좌표는 실제 캔버스의 정수 픽셀이다.
- 각 윤곽이 독립적인 연결된 발 하나를 가리킨다. 두 윤곽의 불투명 픽셀이 겹치지 않고, 반대 발이 ROI 안에 들어가지 않는다.
- 선언된 발 전체가 ROI 안에 있으며, ROI의 불투명 픽셀 전부가 해당 발에 속한다. 밑창을 제외하거나 일부만 추적하지 않는다.
- 굽·앞창 표식은 실제 하단 띠의 불투명 픽셀에 있고, 두 접촉면이 있다면 각각 하나씩 가리킨다.
- 두 접촉면 사이 간격은 발 외곽 너비의 30% 이내이며, 위로 합쳐지는 깊이는 발 높이의 20%와 너비의 12%를 올림한 값 중 작은 값 이내다.
  이는 현재의 보수적인 형상 제한이지 해부학 판정의 정확도 확률이 아니다. CLI로 한계를 느슨하게 바꿀 수 없다.
- 공식 검사의 다른 실패(잘림, 면적/크기 변화, 수직 이동, 역방향 전환, 속도 불일치, 관찰 자세 부족 등)가 하나도 없다.

조건을 만족했을 때만 기존에 계산된 후보 속도를 검증값으로 채택한다. 속도를 수기로 받지 않는다.
두 발이 섞였거나, 근거가 없거나 오래됐거나, 깊고 넓은 틈/3개 이상 접촉면이면 계속 미검증이다.
보행 루프·정체성·해부학·양발 교대의 시각 검수와 최종 패키징 게이트는 별도로 유지된다.

### v2: 발가락 패드·발굽·발톱과 발가락 보행

동물 발은 사람 발 가정과 두 곳에서 어긋난다. 발가락 패드·갈라진 발굽·발톱이 하단 2픽셀 띠를 세 갈래 이상으로 나누고,
발가락 보행(digitigrade)이나 뒤꿈치 떼기에서는 뒤꿈치가 들리면서 ROI 안 발 면적·외곽·중심이 바뀐다.
공식 검사는 이것을 "여러 접촉면", "면적/크기 변화", "중심 수직 이동", "속도 불일치"로 본다. 앞의 둘은 발 정체성,
뒤의 둘은 이동을 **ROI 실루엣으로 대신 재는 지표**다. v2는 이 지표를 양발 윤곽과 실제 접지 픽셀로 바꿔 잰다.
v1의 공통 조건(픽셀·시간·구간·ROI 고정, 양발 윤곽, 반대 발 제외, ROI 전체가 그 발, 시각 검토 네 항목)은 그대로다.

- **접촉 갈래는 발 단위로 묶는다.** 윤곽으로 한 발임을 확인한 뒤 하단 띠의 갈래 수는 제한하지 않는다. 단 갈래 사이 가장 넓은 틈이
  발 외곽 너비의 30% 이내이고, 모든 갈래가 v1과 같은 얕은 깊이(발 높이 20%·너비 12% 올림 중 작은 값) 안에서 하나로 합쳐져야 한다.
  두 발이 위쪽에서만 이어진 경우처럼 깊거나 넓은 틈은 여전히 미검증이다. 한계 숫자는 v1과 같고 CLI로 바꿀 수 없다.
- **앞발은 땅에, 뒤꿈치는 들려도 된다.** `forefoot`는 매 프레임 실제 하단 띠의 그 발 픽셀이어야 한다. `heel`은 그 발의 픽셀이면
  띠 위로 들려도 되며 보고서에 `heelLifted`로 남는다. 바라보는 방향 순서(뒤꿈치가 뒤)는 유지한다.
  뒤꿈치만 닿고 앞발이 뜬 프레임(사람의 뒤꿈치 착지)은 구간에 넣지 않는다.
- **이동은 앞쪽 접지 끝에서 잰다.** 오른쪽을 보면 하단 띠의 가장 오른쪽 픽셀, 왼쪽을 보면 가장 왼쪽 픽셀이다.
  앞발 끝은 발바닥이 다 닿은 때(또는 발가락 착지)부터 발가락 떼기까지 땅에 남는 마지막 부분이라, 뒤꿈치가 들려도 움직이지 않는다.
  공식 검사와 같은 자세 시작 프레임·시간, 끝점 속도, 역방향(±0.25px)·순이동 1px 미만·RMSE > max(0.5, 이동 범위의 10%) 공식을
  그대로 쓴다. 바뀌는 것은 추적하는 x 하나뿐이다. 결과는 `foot_evidence.contactTrack`에 남는다.
- **풀리는 공식 사유는 정해져 있다.** 위 실루엣 대리 지표 7개(여러 접촉면, 중심 수직 이동, 면적 변화, 크기 변화, 역방향,
  순이동 부족, 속도 불일치)만 v2 측정이 통과할 때 풀리며 `foot_evidence.resolvedReasons`에 적힌다.
  바닥선이 1px 넘게 움직임(공중), ROI 가로 경계 닿음, ROI 안 분리된 모양, 서로 다른 자세 3개 미만, 그리고 앞으로 공식 검사에
  새로 생길 사유는 근거로 풀리지 않는다.

v2에서도 계속 잡히는 진짜 오류: 앞쪽 접지가 미끄러지거나 속도가 들쭉날쭉함, 역방향, 제자리, 발이 뜸(바닥선 이동),
반대 발이 ROI에 들어옴, 깊거나 넓은 틈, 앞발이 땅에 없음, 오래된 근거. 같은 발이 이어서 딛는 것은 보행 계획의
양발 교대 검사, 두 발의 속도 차 25% 초과는 `fighter:gait review`의 `STANCE_SPEED_DISAGREEMENT`가 잡는다.

#### 실제 사례: 고양이 복서 (2026-10-26, 내부 테스트 선수)

Grok walk 16칸·run 12칸. 공식 검사로는 walk far가 발가락 패드 2~3갈래, run이 뒤꿈치 들림 면적 25%↑ 변화로 미검증이었다.
같은 프레임·같은 ROI에 v2 근거(알파에서 따낸 윤곽을 겹쳐 그린 그림으로 눈 확인)를 붙인 결과:

| 구간 | 공식 사유 | v2 |
|------|-----------|----|
| walk near 5-7 | 없음 | 검증, 앞쪽 접지 −480 px/s |
| walk far 10-12 | 여러 접촉면, 속도 불일치 | 미검증 — 10·11은 2갈래가 깊이 4에서 합쳐져 통과, 12에서 near 발끝이 far ROI에 들어옴(`OTHER_FOOT_IN_ROI`) |
| walk far 9-11 | 여러 접촉면, 바닥선 이동 | 미검증 — 9는 착지 프레임이라 바닥이 2px 다름(풀리지 않는 사유) |
| run near 2-4 | 면적 변화, 속도 불일치 | 검증, −614 px/s (뒤꿈치 세 프레임 모두 들림) |
| run far 8-10 | 바닥선 이동, 면적·크기 변화 | 미검증 — 바닥 2px 이동, 앞쪽 접지도 27→62px로 속도 불일치 |
| run far 9-11 | 면적·크기 변화 | 검증, −781 px/s |

walk는 far 접지를 잴 3프레임 구간이 없어 `unverified`, run은 near −614와 far −781이 25% 넘게 달라 `fail`(`STANCE_SPEED_DISAGREEMENT`)이다.
남은 것은 발 모양이 아니라 움직임 자체다. 프레임 간 이동이 고르지 않다(walk near 3→8 앞쪽 접지 33·12·34·21·13px).
22→16·19→12칸을 가장 가까운 원본 프레임으로 고른 탓으로 보인다. 같은 속도로 이동하는 게임에서는 디딘 발이 앞뒤로 미끄러져 보인다.
지나가는 프레임에서 앞발이 뒷발 ROI를 가리는 문제는 고정 ROI 방식의 한계로 남는다.

## 사용 순서

먼저 일반 `fighter:gait review`를 실행해 현재 프레임의 `review/measurement/sequence.json`을 만든다.
다음은 **명령 구조 예시**다. 발 전체를 포함하는 실제 접지 구간과 ROI로 바꾼다. 기존 좁은 ROI가 부츠 윗부분을 잘랐다면
발 전체를 보며 다시 지정한다. 통과하는 좌표를 탐색해서 선택하지 않는다.

```sh
npm run fighter:contact -- template --source review/measurement/sequence.json --contacts 1:3 --foot-box 232,400,126,61 --foot near --facing right --out near-foot.json
```

템플릿의 `sequence`·`stance`는 편집하지 않는다. 이미지나 ROI가 바뀌면 새 파일로 템플릿을 다시 만든다. 기존 파일은 덮어쓰지 않는다.
`review.reviewer`에는 실제 검토 주체(예: agent visual review)를, `notes`에는 어떤 그림에서 어떻게 같은 발을 구분했는지 기록한다.
`method`는 `visual-per-frame`이며 네 검토 항목을 실제 관찰에 따라 `pass`로 바꾼다. 추정으로 통과시키지 않는다.

각 `frames` 항목을 다음 구조로 채운다. 아래 빈 배열은 그대로는 미검증이다.

```json
{
  "frame": 1,
  "nearOutline": [],
  "farOutline": [],
  "heel": [],
  "forefoot": []
}
```

윤곽은 `[[x,y], ...]` 3~128개 꼭짓점이고 처음 점을 끝에 반복하지 않는다. `heel`·`forefoot`는 측정할 발의 `[x,y]`다.
반대 발의 윤곽도 실제로 표시한다. 동일 좌표를 모든 프레임에 복사하거나, 다른 발을 몸통으로 표시해 제외하지 않는다.

확인용 단독 실행:

```sh
npm run fighter:contact -- inspect --source review/measurement/sequence.json --contacts 1:3 --foot-box 232,400,126,61 --foot near --facing right --foot-evidence near-foot.json --out near-contact.json
```

양쪽 접지 구간 각각의 근거를 만든 뒤 annotations의 해당 stance에 `footEvidence` 경로를 넣는다.
이 경로는 **annotations JSON의 폴더 기준**이다. `box`, `start`, `end`는 증거 파일과 일치해야 한다.

```json
{"foot":"near","start":1,"end":3,"box":[232,400,126,61],"footEvidence":"near-foot.json"}
```

```sh
npm run fighter:gait -- review walk-plan.json review annotations.json
```

새 보고서의 `measurement_engine`은 근거 판에 따라 `ai-fighter-foot-evidence-v2` 또는 `-v1`이다. 공식 결과는 `upstream_report`,
추가 판정·윤곽·검토는 `foot_evidence`에 남는다. v2는 프레임별 `leadingContactX`·`heelLifted`, `contactTrack`, `resolvedReasons`도 남긴다. 단독 접지 측정이 성공해도 전체 보행이 실패하면 `review.json.status`는 실패이고 보폭은 `null`이다.
등록 전 미리보기의 지면·접지 영역 표시를 켜면 선언한 양발 윤곽과 굽·앞창 점도 실제 프레임 위에 겹쳐진다.
최종 game-pack의 픽셀이나 배율·시간이 달라지면 새 템플릿과 새 윤곽 검토가 필요하다. `fighter:pack`은 최종 시퀀스와 맞는 근거만 받는다.

## 회귀 검사

```sh
node --test test/contact-evidence.test.mjs test/gait.test.mjs test/gait-engine.test.mjs test/pack.test.mjs
```

실제 번들 검사기와 합성 측정 fixture로 v1: 단일 부츠의 조건부 통과, 연결된 두 발/분리된 두 발/잘못된 ROI/밑창 잘림/
미할당 픽셀/근거 누락/해시·시간 변경/접촉점 오류/깊은 틈/공중 이동/속도 불일치/시각 루프 실패를 확인한다.
v2: 패드 세 갈래·뒤꿈치가 들리는 발의 통과(속도는 발끝 기준 −80 px/s), 같은 부츠 fixture의 v2 속도가 v1과 같음,
발끝 미끄러짐/역방향/제자리, 공중, 앞발 들림, 뒤꿈치 위치 오류, 깊은 틈·넓은 패드 틈, 반대 발 ROI·ROI 경계, 오래된·미검토 근거의 실패,
보행 게이트가 v1·v2 근거 모두에서 같은 보폭(128px)을 내고 판이 섞인 근거를 거절함을 확인한다. 합성 fixture는 등록 가능한 캐릭터가 아니다. Rook 등 실제 캐릭터의 윤곽과 검토를 대신하지 않는다.
