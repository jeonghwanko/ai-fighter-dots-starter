# 제작 과정 평가 — 2026-10-21

평가 대상은 Dot으로 캐릭터를 만드는 대화·도구 실행 과정이다. 특정 캐릭터 그림의 취향 평가가 아니다.
근거는 이번 대화, 도구 응답, 별도 체크아웃의 가이드 변경이다. 일반 사용자 여러 명을 대상으로 한 연구는 수행하지 않았다.

## 결론

**이번 테스트는 범위 설정을 고쳐야 하며, 제작 과정 전체의 합격 판정은 보류한다.**
최초 입력은 GitHub 링크 한 줄이었고, 에이전트는 캐릭터·화풍을 물어 정상적으로 시작했다.
이후 다른 채팅에서 전달된 고양이 문장은 “만들고 싶어”였으며, 테스트 데이터이거나 실제 생성을 금지한다는
범위 표기가 없었다. 따라서 그 시점의 생성 시작을 명백한 제작 에이전트의 지시 위반으로만 평가하는 것은 부정확하다.

전체 작업의 목적은 과정 개선·평가였으나, 전달된 작업 문장은 실제 제작으로 읽힐 수 있었다.
이는 우선 **테스트를 전달하는 쪽의 범위 설정 결함**이다. 제작 에이전트 쪽에는 사용자의 메타 수준
질문에서 목표를 재해석하고, 명확해진 설계·평가 목적에 맞춰 즉시 전환하는 개선이 필요하다.
이미지 엔진 성공은 이 범위 불일치를 해소하지 않는다. 반대로 생성 성공만으로 지시 위반을 입증할 수도 없다.

수정한 가이드는 이 실패와 질문 중복을 방지하는 행동 규격을 추가했다.
현재 확인 수준은 **문서 대조**다. 수정 후 에이전트가 같은 상황에서 올바르게 행동하는지,
다양한 참조 이미지와 동작을 실제로 잘 만드는지는 별도의 실행 평가가 필요하다.

## 실제 관찰과 판정

| 항목 | 관찰 근거 | 판정 |
| --- | --- | --- |
| 최초 진입 | GitHub 링크만 받은 뒤 원하는 캐릭터와 그림 느낌을 질문하고 예시를 제시 | 관찰한 초기 응답은 적절 |
| 테스트 범위 전달 | 전달 문장은 “고양이 복서로 만들고 싶어”였고 실제 생성 금지·시뮬레이션 범위 표기가 없었음. 나중에 테스트용이었다고 확인 | 테스트 설계 결함; 명시적 생성 금지 위반으로 판정하지 않음 |
| 목적 재해석 | 사용자가 입력 가이드·UX 최적화·과정 평가가 목적임을 반복해 설명한 뒤 문서 작업으로 전환 | 메타 요청의 조기 식별 개선 필요 |

| 전신·얼굴·사용자 선택 | 전신 파일은 생성·열람됐으나 얼굴 확대와 정식 외형 선택까지 진행하지 않음. 실제 목표가 과정 개선으로 명확해짐 | 정당한 외형 리뷰 단계 평가 N/A |
| 텍스트+이미지 입력 | 실제 참조 이미지 입력·역할 충돌 사례를 실행하지 않음 | 미검증 |
| 동작·최종 패키지·등록 | 이번 평가에서 생성·검수·등록하지 않음 | 미검증 |
| 목적 변경 대응 | 명확한 정정 후 새 생성 없이 프로세스 문서·평가로 전환. 이미 끝난 테스트 결과는 작업 자료로 보존 | 전환 확인; 후속 묶음의 수락·전환 행동은 관찰하지 못함 |

66.594초는 한 번의 생성 엔진 호출 시간이다. 설치·질문·대화 시간을 포함한 첫 결과 도달 시간이나 평균 생성 속도가 아니다.
테스트 범위가 일관되지 않았고 전체 품질 항목도 평가되지 않았으므로 100점 환산 총점은 제시하지 않는다.

U01–U16은 [평가 시나리오](CREATION-UX.md)의 식별자다. 표는 문서에 기대 행동이 정의되어 있음을 뜻한다.
테스트를 실행해 통과했다는 뜻이 아니다. 제품 코드나 vendored sprite-gen은 변경하지 않았다.

## 다음 검증의 합격 기준

1. **도구 호출 없이 대화 평가.** [평가 요청 양식](CREATION-UX.md#평가-요청의-실행-범위)으로 모의 입력과 실행 금지를 먼저 명시한다.
   새 대화에서 U01–U16을 각각 입력한다. 평가자가 먼저 기대 행동을 정하고,
   실제 응답·질문·예정된 도구 호출을 기록한다. 같은 문서를 작성한 에이전트의 자기 확인만으로 합격 처리하지 않는다.
2. **최소 실제 생성 평가.** 사용자가 실행을 요청한 텍스트, 이미지+수정, 여러 참조의 세 유형으로 외형을 만든다.
   전신과 동일 원본 얼굴 crop을 전달하고, 필수 특징 누락·불필요한 질문·생성 횟수·시간·사용자 피드백을 기록한다.
   세 유형을 다룬 것은 최소 기능 확인이며 통계적 품질 보장이 아니다.
3. **동작 평가.** 선택된 외형에 대해 다섯 묶음 경계와 부분 수정 처리를 실제로 관찰한다.
   보행·접지·루프·정체성·공격 박자는 실제 애니메이션과 최종 파일의 검수 근거로 평가한다.
4. **오류와 재개 평가.** 제공자 오류·한도·타임아웃·중단·재개 상황에서 무단 전환과 중복 생성이 없는지 확인한다.
   가능하면 재현 가능한 모의 오류로 먼저 검사하며, 실계정 한도를 소진시키는 시험은 하지 않는다.
5. **최종 판정.** 모든 필수 게이트 통과와 전체 품질 점수 80/100 이상을 초기 목표로 삼는다.
   미검증 항목이 있으면 부분 검증으로 표시하고 전체 통과라고 하지 않는다.

질문 횟수 자체를 무조건 줄이지 않는다. 이미 답한 내용을 다시 묻는 질문은 결함이고,
실제 결과를 바꾸는 참조 충돌을 해결하는 질문은 품질에 필요한 대화다.

## 통합 시 주의할 지점

- 최초 수정은 별도 체크아웃의 README, AGENTS, START-HERE, DOT-CREATION 및 새 UX·평가 문서에 작성했다.
  이 기록은 당시 관찰 결과다. 후속 GitHub 통합은 수정 후 대화 실행 시험이나 실행 중 MCP 교체를 뜻하지 않는다.
- 이번에 연결된 MCP의 creation 응답은 이전 로컬 키트의 문서를 반환했다.
  문서 통합 후 실제 MCP가 새 가이드와 같은 버전을 반환하는지 확인해야 한다.
- 제공자 기본 순서는 사용자가 정한 제품 방향이다. GPT/Grok 조합별 우열은 여러 캐릭터의 실제 결과와 비용·시간을 비교하기 전까지 확정하지 않는다.
- 테스트용 생성 파일은 작업 자료로만 남긴다. 사용자가 선택한 캐릭터·제작 예시의 품질 검증 결과로 배포하지 않는다.
