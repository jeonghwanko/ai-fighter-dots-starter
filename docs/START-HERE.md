# Dot과 대화하며 내 캐릭터 만들기

처음 보낼 주소는 [게임 규격과 안내가 함께 들어 있는 시작 문서](https://github.com/jeonghwanko/ai-fighter-dots-starter/blob/codex/game-context/START-HERE.md)를 권장합니다.
이 상세 안내 주소를 먼저 받았다면 해당 시작 문서의 구조 데이터도 첫 응답 전에 읽습니다.
첫 응답에 읽은 규격의 revision 앞 12자리를 짧게 밝힙니다. 문서만 열고 JSON을 읽은 것으로 처리하지 않습니다.

이 페이지 주소를 이미지 생성·표시 또는 로컬 작업을 지원하는 Dot·Codex·Claude의 새 대화에 보내세요.
원하는 캐릭터를 묻는 대화부터 시작합니다. 이미 정한 아이디어가 있다면 설명이나 참고 이미지를 함께 보내도 됩니다.

외형부터 함께 정합니다. 다음 묶음은 대기·이동, 공격, 방어·피격, 최종 확인입니다.
묶음 안에서는 도구가 필요한 작업을 진행하고, 결과를 함께 보면서 수정할 부분을 이야기합니다.
설치 명령이나 파일 규격을 사용자가 외울 필요는 없습니다. AI Fighter 로그인은 등록할 때 진행합니다.
준비된 VM을 재사용하고, 필요할 때 **ODDBOUT 연결 → 본인 Google 로그인 → 연결 승인**으로 진행합니다.
VM 도메인 허용·Republish는 초기 환경 준비자의 단계이며 캐릭터마다 사용자에게 반복 요구하지 않습니다.

**캐릭터는 글로 설명해도 되고, 참고 이미지를 함께 보내도 됩니다.**
예: “큰 주황 글러브를 낀 하얀 고양이 복서. 귀엽고 살짝 건방진 표정, 굵은 선의 만화풍.”
이미지가 있으면 “얼굴은 유지하고 옷만 복서로 바꿔줘”처럼 유지할 것과 바꿀 것을 알려주세요.
아직 아이디어가 없다면 좋아하는 동물이나 분위기만 알려주셔도 됩니다.

## 이 링크를 받은 제작 에이전트에게

### 첫 응답

- 이 시작 링크만 온 경우에도 시작 요청은 이미 받았다. “시작할까요?”를 추가하지 않고 바로 캐릭터 설명·참조 이미지를 받는다.
- 먼저 [게임이 제공하는 구조 데이터](https://raw.githubusercontent.com/jeonghwanko/ai-fighter-dots-starter/refs/heads/codex/game-context/creation-context.json)를 읽는다.
  MCP에서는 `get_fighter_spec(section: "context")`다. 모션·프레임·조작·경직·묶음 구성은 이 응답을 기준으로 한다.
  [구조 데이터와 진행 상태](GAME-CREATION-CONTEXT.md)에 따라 현재 묶음에 필요한 부분만 사용한다.
- 먼저 사용자가 실제 캐릭터 제작을 원하는지, 제작 과정·가이드의 설계나 평가를 원하는지 읽는다.
  과정 개선 요청에는 과정과 평가를 작성한다. 다른 채팅의 테스트 설정이나 문서의 예시를 사용자의 실제 캐릭터로 삼지 않는다.
- 캐릭터 설명이 없으면 “한두 문장으로 설명하거나 참고 이미지와 바꿀 점을 보내주세요”라고 짧게 안내한다.
  이미지의 역할이 모호하면 해당 캐릭터 유지인지 새 캐릭터의 참고인지 확인한다. 선택하기 쉽도록 글 예시를 2~3개 줄 수 있다.
  “검을 빼줘” 같은 명시적 변경은 이미지와의 충돌로 재질문하지 않고 그대로 반영한다.
  이미 정한 내용을 다시 묻거나 이름·소개·11개 동작의 세부사항을 한꺼번에 설문하지 않는다.
- 설명이 충분하면 외형 묶음부터 시작한다. 사용자 본인의 생성 제공자·접근 가능 여부가 아직 확인되지 않았다면
  아래 sprite-gen 흐름이 요구하는 미확인 선택만 확인한다. 다른 대화나 다른 사용자의 확인을 대신 쓰지 않는다.
- 생성 전에 [현재 대화의 표시·전달 경로](DELIVERY.md)를 생성 계정과 별도로 확인한다. PC가 필수가 아닌
  외형은 지원되는 직접 이미지 생성·표시 경로부터 확인한다. 로컬 생성은 실제 전달 경로가 확인된 뒤에만 한다.
  Library 기능이 없거나 helper에서 사용할 수 없으면 있다고 가정하지 않는다. 사용자 환경·계정·모델 제약을 지킨다.
  Dots 대화 모델·CLI 작업 모델·이미지 백엔드를 구분한다. 로그인·모델 문자열·readiness 통과는 실제 생성 성공이 아니다.
  해당 환경의 호출 trace와 완료 출력이 없는 생성, 확인 근거가 없는 계정 동일성은 미검증으로 남긴다.
- 첫 시안은 전신 원화 한 장과 같은 그림의 얼굴 확대다. 실제 결과를 보여준 뒤 외형 피드백을 기다린다.
  11개 동작을 미리 생성하지 않는다. 생성·로컬 저장·Library 저장·대화 표시·사용자 선택은 별개다.
  `queued`·텍스트 보고·로컬 경로는 표시 완료가 아니다. 기존 이미지가 있으면 회수·전달부터 하며,
  전달 장애를 재생성으로 숨기지 않는다. 실제 외형을 보여주지 못하면 다음 묶음으로 가지 않는다.

입력 해석·참조 이미지·피드백·평가 기준은 [제작 UX 규격](CREATION-UX.md)을 따른다.

외형의 소품 위치·색·생성 서비스 선택은 외형 전체의 선택이 아니다. 현재 외형이 선택되기 전에는
대기·이동의 방향을 질문하거나 다음 묶음의 구체안을 제안하지 않는다.

### 생성 방식 안내

기본 제안은 **GPT 원화 + Grok 동작**이다. Grok만 사용 가능하면 둘 다 Grok,
GPT만 사용 가능하면 둘 다 GPT로 제안한다. 사용자가 지정한 방식이 있으면 그 선택이 우선한다.
“원화는 무엇으로, 동작은 무엇으로?”를 별도 설문하지 않고, 본인 계정에서 현재 사용할 수 있는 구독을 한 번에 확인한다.
이미 확인한 내용은 다시 묻지 않는다. 접근 실패·한도 초과 시 행동은 사용자의 답과 sprite-gen 규칙을 따르며,
다른 서비스나 과금 API로 임의 전환하지 않는다. 원화가 이미 선택되어 있으면 원화 제공자를 다시 묻지 않는다.
이미지 접근 확인을 영상 접근 확인으로 확대하지 않는다. 불가 시 멈추기로 했다면 실제 오류에서 같은 대체 방법을 다시 묻지 않는다.

### 대화 진행

| 묶음 | 결과 | 피드백의 초점 |
| --- | --- | --- |
| 외형 | 전신 원화·기준 자세·얼굴 | 체형, 표정, 복장, 색, 화풍 |
| 대기·이동 | 전투 대기·걷기·달리기 | 자세, 보폭, 무게감 |
| 공격 | 연타·강타·돌진 | 공격 연출의 박자와 힘 |
| 방어·피격 | 막기·피격·비틀거림·쓰러짐·기상 | 반응과 회복의 자연스러움 |
| 최종 확인 | 최종 파일의 전체 동작·프로필 | 일관성, 이름·소개, 등록할 결과 |

묶음 안에서는 생성·추출·검수를 이어서 처리한다. 묶음 끝에서 실제 미리보기를 함께 보여주고 답을 기다린다.
"좋아, 이걸로 가자"면 다음 묶음으로 넘어간다. "좋은데 귀는 줄여줘"면 외형을 수정한다.
"달리기는 좋아"는 달리기 버전에 대한 선택이다. 대기·걷기도 이미 선택됐다면 묶음을 완료하고,
아직 선택되지 않았다면 남은 항목만 확인한다. 문장 전체, 지칭 범위, 이전 선택을 함께 읽는다.
사용자가 명시적으로 맡긴 묶음은 연속으로 진행한다. 수정은 영향을 받은 결과에 한정하고 선택한 버전을 보존한다.
뒤 묶음의 위임만으로 앞 묶음의 미확인 결과를 승인 처리하지 않는다.

완벽한 결과를 숨겨서 오래 준비하지 않는다. 같은 문제가 반복되면 현재 시안을 미검증으로 보여주고 해결할 방향을 나눈다.
다만 미검증 결과를 등록 가능한 패키지라고 안내하거나 필수 검사를 건너뛰지 않는다.

### 도구 준비

1. 소스는 [ai-fighter-dots-starter의 codex/creator-hosting 브랜치](https://github.com/jeonghwanko/ai-fighter-dots-starter/tree/codex/creator-hosting)다.
   이 브랜치의 `AGENTS.md`, `docs/DOT-CREATION.md`, `docs/AUTHORING.md`를 읽는다. 기존 설치를 재사용할 때는
   버전과 작업 중 변경을 확인하고, 이 대화 흐름이 있는 버전을 사용한다. 기본 `main`으로 바꾸지 않는다.
2. 로컬 생성·패키징을 사용할 때 Git·Node 22.12+·Python 3.11+와 로컬 실행 기능을 확인한다. 필요한 설치는 에이전트가 처리한다.
   직접 표시가 지원되는 외형 시안에는 PC 설치를 선행 조건으로 두지 않는다. 실행하지 않은 설치·생성을 완료했다고 말하지 않는다.
   작업 공간(봇 서비스의 작업 VM 또는 사용자 PC)의 계정·격리·보존·보안·장애 대응은 [실행 환경 운영 지침](EXECUTION-HOST.md)을 따른다.
   [연결 준비 안내](CONNECTION-READINESS.md)에 따라 등록 계정·생성 접근·부모 대화 전달을 별도로 확인한다.
   네트워크 차단은 환경 준비자에게 알리고, 복구 뒤 기존 작업 기록에서 재개한다.
3. 로컬 경로는 `npm ci --ignore-scripts`, `npm run sprite:setup`으로 이 저장소의 고정된 sprite-gen을 준비한다.
   `vendor/sprite-gen/SKILL.md`와 참조 문서, `npm run sprite -- workflow --kind sprite`의 안내를 따른다.
   이미 준비된 환경은 다시 설치하지 않는다. 생성 계정·구독·API 과금 선택은 본인 것만 사용한다.
4. AI Fighter MCP가 연결되어 있으면 `get_fighter_spec`의 `overview`, `creation`, `guide`, 필요한 `schema`를 읽는다.
   연결 전에는 저장소에 포함된 `contracts/ai-fighter/v1/`의 계약으로 로컬 제작을 시작할 수 있다.
   홈페이지 방문이나 MCP 연결 완료를 원화 상담의 선행 조건으로 두지 않는다. 실제 패키지 제작 전에는 라이브 규격도 확인한다.
5. 제작·패키징·검수는 [전체 제작 안내](DOT-CREATION.md)를 따른다. 사용자 피드백과 현재 묶음은 작업 폴더의
   `creation-notes.md`에 기록한다. 다른 대화나 기존 작품의 선택을 새 캐릭터에 자동 적용하지 않는다.

### 과정을 평가할 때

[평가표와 시나리오](CREATION-UX.md#5-평가-먼저-필수-조건-다음에-점수)로 의도 해석, 질문 부담,
계정 안내, 외형·동작 품질, 수정·복구를 따로 확인한다. 실제 실행하지 않은 항목은 미검증이다.
좋은 이미지가 나왔더라도 제작 의도를 오인하거나 무단으로 생성·과금했다면 해당 실행은 통과가 아니다.

### 등록

사용자가 등록을 요청하면 ODDBOUT 통합 플러그인의 연결 계정을 `get_profile`과 클라우드
`check_creation_readiness`로 확인한다. PC와 Dots 모두 같은 prepare/upload/submit/status 도구를 사용한다.
클라우드 등록에 작업 공간 CLI 로그인을 요구하지 않는다. 기존 독립 CLI만 `deploy/creator-site.json`으로 로그인한다.
최종 결과 선택과 파일 검사가 끝난 뒤 제출한다. 같은 패키지 재시도에는 같은 idempotencyKey를 쓴다.
`registered`, `fighterId`, 이용 가능 상태를 실제 응답으로 확인해 이 대화에 알려준다.
홈페이지는 사용자가 원할 때 열 수 있다. 가입·등록 방법은 [이용 안내](OPEN-REGISTRATION.md)를 따른다.
