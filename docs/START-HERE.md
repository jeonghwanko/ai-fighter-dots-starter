# Dot과 대화하며 내 캐릭터 만들기

이 페이지 주소를 로컬 작업이 가능한 Dot·Codex·Claude에 보내고 이렇게 말하세요.

> 이걸로 나와 대화하면서 캐릭터를 만들어보자.

외형부터 함께 정합니다. 다음 묶음은 대기·이동, 공격, 방어·피격, 최종 확인입니다.
묶음 안에서는 도구가 필요한 작업을 진행하고, 결과를 함께 보면서 수정할 부분을 이야기합니다.
설치 명령이나 파일 규격을 사용자가 외울 필요는 없습니다. AI Fighter 로그인은 등록할 때 진행합니다.

## 이 링크를 받은 제작 에이전트에게

### 첫 응답

- 캐릭터 설명이 없으면 원하는 캐릭터와 그림 느낌을 한 번에 짧게 물어본다. 선택하기 쉽도록 예시를 2~3개 줄 수 있다.
  이미 정한 내용을 다시 묻거나 이름·소개·11개 동작의 세부사항을 한꺼번에 설문하지 않는다.
- 설명이 충분하면 외형 묶음부터 시작한다. 사용자 본인의 생성 제공자·접근 가능 여부가 아직 확인되지 않았다면
  아래 sprite-gen 흐름이 요구하는 미확인 선택만 확인한다. 다른 대화나 다른 사용자의 확인을 대신 쓰지 않는다.
- 첫 시안은 전신 원화 한 장과 같은 그림의 얼굴 확대다. 실제 결과를 보여준 뒤 외형 피드백을 기다린다.
  11개 동작을 미리 생성하지 않는다. 원화 생성 성공과 전체 캐릭터 완성을 구분한다.

### 대화 진행

| 묶음 | 결과 | 피드백의 초점 |
| --- | --- | --- |
| 외형 | 전신 원화·기준 자세·얼굴 | 체형, 표정, 복장, 색, 화풍 |
| 대기·이동 | 전투 대기·걷기·달리기 | 자세, 보폭, 무게감 |
| 공격 | 연타·강타·돌진 | 공격 연출의 박자와 힘 |
| 방어·피격 | 막기·피격·비틀거림·쓰러짐·기상 | 반응과 회복의 자연스러움 |
| 최종 확인 | 최종 파일의 전체 동작·프로필 | 일관성, 이름·소개, 등록할 결과 |

묶음 안에서는 생성·추출·검수를 이어서 처리한다. 묶음 끝에서 실제 미리보기를 함께 보여주고 답을 기다린다.
"좋아, 이걸로 가자"면 다음 묶음으로 넘어간다. "좋은데 귀는 줄여줘"면 외형을 수정한다.
"달리기는 좋아"는 대기·이동 전체를 확정한 뜻이 아니다. 문장 전체와 지칭 범위를 읽는다.
사용자가 명시적으로 맡긴 묶음은 연속으로 진행한다. 수정은 영향을 받은 결과에 한정하고 선택한 버전을 보존한다.

완벽한 결과를 숨겨서 오래 준비하지 않는다. 같은 문제가 반복되면 현재 시안을 미검증으로 보여주고 해결할 방향을 나눈다.
다만 미검증 결과를 등록 가능한 패키지라고 안내하거나 필수 검사를 건너뛰지 않는다.

### 도구 준비

1. 소스는 [ai-fighter-dots-starter의 codex/creator-hosting 브랜치](https://github.com/jeonghwanko/ai-fighter-dots-starter/tree/codex/creator-hosting)다.
   이 브랜치의 `AGENTS.md`, `docs/DOT-CREATION.md`, `docs/AUTHORING.md`를 읽는다. 기존 설치를 재사용할 때는
   버전과 작업 중 변경을 확인하고, 이 대화 흐름이 있는 버전을 사용한다. 기본 `main`으로 바꾸지 않는다.
2. Git·Node 22.12+·Python 3.11+와 로컬 실행 기능을 확인한다. 필요한 설치는 에이전트가 처리한다.
   로컬 실행이 없는 환경이면 그 제한을 먼저 알리고, 실행하지 않은 설치·생성을 완료했다고 말하지 않는다.
3. `npm ci --ignore-scripts`, `npm run sprite:setup`으로 이 저장소의 고정된 sprite-gen을 준비한다.
   `vendor/sprite-gen/SKILL.md`와 참조 문서, `npm run sprite -- workflow --kind sprite`의 안내를 따른다.
   이미 준비된 환경은 다시 설치하지 않는다. 생성 계정·구독·API 과금 선택은 본인 것만 사용한다.
4. AI Fighter MCP가 연결되어 있으면 `get_fighter_spec`의 `overview`, `creation`, `guide`, 필요한 `schema`를 읽는다.
   연결 전에는 저장소에 포함된 `contracts/ai-fighter/v1/`의 계약으로 로컬 제작을 시작할 수 있다.
   홈페이지 방문이나 MCP 연결 완료를 원화 상담의 선행 조건으로 두지 않는다. 실제 패키지 제작 전에는 라이브 규격도 확인한다.
5. 제작·패키징·검수는 [전체 제작 안내](DOT-CREATION.md)를 따른다. 사용자 피드백과 현재 묶음은 작업 폴더의
   `creation-notes.md`에 기록한다. 다른 대화나 기존 작품의 선택을 새 캐릭터에 자동 적용하지 않는다.

### 등록

사용자가 등록을 요청하면 `deploy/creator-site.json`의 공개 설정으로 본인의 Google 로그인을 진행한다.
최종 결과 선택과 파일 검사가 끝난 뒤 제출한다. 같은 패키지 재시도에는 같은 idempotencyKey를 쓴다.
`registered`, `fighterId`, 이용 가능 상태를 실제 응답으로 확인해 이 대화에 알려준다.
홈페이지는 사용자가 원할 때 열 수 있다. 가입·등록 방법은 [이용 안내](OPEN-REGISTRATION.md)를 따른다.
